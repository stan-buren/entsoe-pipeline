# PULL REQUEST: FMS Metadata Catalog Migration to PostgreSQL & Pipeline Hardening

## Summary

This pull request migrates the ENTSO-E File Management System (FMS) metadata catalog from flat YAML files to a PostgreSQL-backed transactional store. It introduces incremental delta refresh logic, eliminates the 68-second `pd.to_datetime` bottleneck (now ~0.06s via stdlib), implements a Leaky Bucket client-side throttler, consolidates the ingestion CLI, establishes database preflight checks, and lays the foundation for the Lakehouse staging layer (Iceberg table generation, incremental file selection, ingestion status registry).

The PR follows Clean Architecture principles: low-level data access (`db/core/`), business logic (`lakehouse/`, `fms_metadata/core/`), and application orchestration (`jobs/`) are cleanly separated with no circular dependencies.

### E. Client-Side Throttler: Sliding Window → Leaky Bucket

* **[MODIFY] `src/entsoe_pipeline/api/client_side_throttler.py`:** Complete rewrite of the rate-limiting algorithm.
  * **Before:** Sliding window — bursts 95 requests instantly, then sleeps a full 60-second window.
  * **After:** Leaky Bucket — uniform pacing with `min_interval_seconds` gating. Each request measures elapsed time since the last dispatch and sleeps only the remaining delta. Zero idle overhead when DB writes take longer than the interval.
  * **Log noise fix:** Sleeps < 1 second are logged at `DEBUG` level instead of `WARNING`, eliminating log spam during micro-throttling (was flooding Kestra logs with hundreds of "sleeping 0.03s" warnings).
  * Constructor signature changed from `(max_requests, period_seconds)` to `(min_interval_seconds)` — the interval is pre-calculated from `entsoe_api_limits.yml` at call site, keeping this class free of config-loading logic.

### F. Performance: 68-Second Bottleneck Eliminated

* **[MODIFY] `src/entsoe_pipeline/fms_metadata/core/fms_metadata_delta.py`:**
  * **Root cause:** `parse_db_timestamp()` called `pd.to_datetime()` 74,491 times in a Python loop. Each call incurred Pandas C-boundary overhead and internal format detection.
  * **Fix:** Replaced `pd.to_datetime(val)` with `datetime.fromisoformat(val.replace("Z", "+00:00"))`. This is stdlib-native (Python 3.11+), zero-overhead per call.
  * **Benchmark results:** 67.1 seconds → 0.059 seconds. **1,140× speedup.**
  * **Secondary fix:** Consolidated two sequential database queries (files + folder states) into a single connection session, eliminating an extra TCP round-trip and connection pool initialization.
* **[ADD] `src/entsoe_pipeline/fms_metadata/core/fms_metadata_delta.py:129`:** Detailed timing logs — `"Successfully retrieved %d files and %d folder states from database in %.2f seconds"` — making pipeline performance transparent and debuggable.

## 8. Breaking Changes

* **`ThrottledSession` constructor:** Changed from `ThrottledSession(max_requests=N, period_seconds=S)` to `ThrottledSession(min_interval_seconds=S/N)`. Callers must pre-calculate the interval. The interval value is sourced from `entsoe_api_limits.yml` via `RateLimitsConfig.fms_min_request_interval_seconds`.
* **`FmsColumnSchema` and `FmsPublicationSchema`:** Now imported from `entsoe_pipeline.config.config_loader` (was `entsoe_pipeline.config.core`). Backward-compatible — both paths work.
* **`physical_catalog/` directory deleted:** Any scripts reading these YAML files must be updated to query PostgreSQL instead.
* **9 ingestion scripts deleted:** Use `fms_metadata_ingest.py --domain <name>` instead.
